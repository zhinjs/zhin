# ADR 0052：Console 信息架构——状态、功能、运维、访问控制分区

状态：Accepted（2026-11-11）；插件页放置规则（插件页面按 `metadata.section` 落到分区、未声明的落到「功能」）由 [ADR 0063](./0063-console-plugin-ui-unification.md) D6 修订：插件页面挂成插件详情页签，Sandbox 例外（D12）。

## 背景

Console 的导航随功能逐个追加，按「实现模块」而不是「要做的事」组织：功能配置散在插件详情里，账号连接没有独立页面，数据库、配置文件、定时任务、环境变量与业务页面混在同一层。ADR 0049（访问控制）、0050（三级功能配置）、0051（终端）各自需要页面落点，需要先定分区。

## 决策

导航分为六个区。前四个是「日常」，后两个是「管理」，视觉上分组；没有权限的区整体隐藏。

| 区 | 回答的问题 | 页面 | 权限 |
|---|---|---|---|
| **概览** | 现在怎么样？ | 仪表盘、日志、Agent 观测 | `status.view` |
| **会话** | 在和谁说话？ | 账号工作区（会话、收件箱、请求通知）、沙盒 | `endpoint.view` / `endpoint.operate` |
| **功能** | 机器人能做什么、在哪里做？ | 功能矩阵、全局配置、适配器、账号配置、AI 与模型 | `feature.*`、`agent.*` |
| **插件** | 装了什么？ | 已安装、市场、插件详情（版本、依赖、日志，不含配置） | `plugin.manage` |
| **运维** | 宿主机怎么样？ | 数据库、配置文件、环境变量、定时任务、文件、终端 | `ops.*` |
| **访问控制** | 谁能做什么？ | 用户、角色、API 令牌、审计日志 | `iam.*` |

### 功能区的路由

| 路由 | 页面 |
|---|---|
| `/features` | 功能矩阵：行为功能，列为「全局」+ 每个适配器实例；每格是三态开关（启用 / 禁用 / 被上级禁用并锁定），标记有覆盖的格子；点击功能名进全局配置，点击格子进对应层级 |
| `/features/global/:plugin` | 全局配置（Schema 表单，即原插件详情里的配置页） |
| `/features/adapters` | 适配器列表（实例别名、类型、账号数、在线数） |
| `/features/adapters/:adapter` | 适配器页：该适配器下的功能覆盖（只列声明了 `adapter` 层的功能）+ 账号连接管理（增删改启停） |
| `/features/adapters/:adapter/endpoints/:endpoint` | 账号配置：该账号的功能覆盖；会话区的账号工作区放一个「功能配置」入口跳过来 |
| `/features/ai` | AI 与模型（模型路由、技能、Ambient、场所，原有页面平移） |

层级配置页的统一交互（沿用模型路由页的层级选择器模式）：

- 每个字段显示有效值与来源徽标：「继承自全局」「继承自适配器」「在此覆盖」。
- 编辑一个继承字段即创建覆盖；覆盖字段旁有「移除覆盖」，回到继承。
- 启用开关在上级禁用时锁定，并说明「已在 全局 / 适配器 qq 禁用」，附跳转链接。
- 只支持全局的功能，在适配器 / 账号页面不出现；只支持全局的字段在下级表单里只读显示。

### 迁移

- 旧路由保留重定向（插件详情的配置页 → `/features/global/:plugin`，旧的数据库 / 配置 / 定时任务页 → `/ops/*`），至少保留一个小版本。
- 插件贡献的页面（`pages/`）按 `metadata.section` 落到对应区；未声明的落到「功能」。

## 后果

- 「配置功能」和「管理插件」分开：插件区只负责装卸与版本。
- 运维与访问控制是独立区，默认只有 `owner` / `admin` 看得到。
