# Choose a solution by outcome

You don't need to learn Zhin's package layout first. Find what you want to build in the table below; each path starts from a minimal system that runs, then adds capabilities as you need them.

| What you want to deliver | Start here | You are done when |
| --- | --- | --- |
| A bot that receives and sends messages | [IM Bot path](/en/paths/im-bot) | Sandbox and a real platform share the same command and message flow |
| Set reminders without AI | [Create reminders with natural time](/en/solutions/reminders) | Review the exact date, timezone and content, then persist a reminder to the original conversation |
| Send feed updates to a specific conversation | [Administrator RSS subscriptions](/en/solutions/rss-subscriptions) | After a baseline check, new articles reach the exact target; tasks can be paused or cancelled |
| A bot that understands your business | [Give the AI business context](/en/authoring/agent-tools#give-the-ai-business-context) | Console's capability catalog shows your Prompt Section is active |
| Tools, MCP, skills, and sub-agents | [AI Agent path](/en/paths/ai-agent) | The Agent sees only capabilities authorized for the current turn |
| Operate and diagnose a deployed bot | [Console Admin path](/en/paths/console) | You can inspect endpoints, logs, capabilities, and Agent runs |
| Operate one product through multiple accounts | [Run one product through multiple accounts](/en/solutions/multi-endpoint-operations) | Each account is diagnosable while business capabilities stay shared |
| Give an Agent business context without excess authority | [Teach an Agent your business without widening its authority](/en/solutions/governed-agent) | Prompts, tools, approvals, and execution policy are independently auditable |
| Use one GitHub repository as a collaboration space | [Use a GitHub repository as a Workroom](/en/solutions/github-workroom) | Repository events enter the right project, and the Workroom is the source of task state |
| A personal schedule, reminder, and voice assistant | [Personal Assistant](/en/showcase/personal-assistant) | Messages, scheduled jobs, voice, and proactive delivery form one loop |
| A multi-platform community bot | [Multi-platform Bot](/en/showcase/community-bot) | Business commands and components do not depend on one adapter |

## Recommended delivery order

1. Get the simplest flow working in Sandbox first.
2. Connect one real platform without leaking adapter details into business code.
3. Enable AI only when needed; govern prompts, tools, and authority separately.
4. Use Console to confirm what is actually running, rather than trusting what the config file says.
