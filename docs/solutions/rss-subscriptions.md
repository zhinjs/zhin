# 把订阅更新发到指定会话

在 Console 的任务中心选择已加载的 RSS 实例，填写源地址和完整目标，创建管理员订阅。首次成功抓取只记住当时的文章，从之后的新文章开始推送；暂停后恢复也不会补发。无需 AI，也无需替某个平台用户发指令。

## 准备插件和目标

先查看用途和安装计划：

```bash
zhin use-cases rss-subscription
zhin install @zhin.js/plugin-rss --dry-run
```

按现有安装流程安装并加载插件，同时配置持久 Database Host、Schedule Host 和支持精确 `sendTarget` 的 Outbound Host。缺少任一能力时，RSS 实例不会发布管理员任务入口。完整配置见[RSS 插件 README](https://github.com/zhinjs/zhin/tree/main/plugins/utils/rss)。

`pollCron` 控制实例轮询间隔，默认每五分钟。调度使用 Host 的实际时区；任务中心显示轮询表达式与最近检查，不推算没有依据的下次执行时间。源站不可达时下一轮重查，不表示已尝试发送。

## 创建并核对

使用当前 Host 的 full scope Token 打开任务中心，选择明确实例和“管理员 RSS 订阅”。输入不带用户名或密码的 HTTP(S) 源地址，再选择投递账号、会话类型与 ID，按实际目标补全父容器和话题。没有会话目录的平台可以手工填写精确 ID；显示名不能代替地址。

核对页面列出的抓取和投递影响后创建。创建只保存任务，不抓取源站、不发送测试消息。等待首次成功检查，任务详情应显示已建立基线。之后用可控测试源新增一篇文章，等待下一轮，再分别核对任务结果和原目标会话。真实平台验证须使用已授权的测试目标；保存成功不等于平台在线或已经投递。

消息使用现有可读文字格式，经统一发送链投递；文章标题、链接及省略数量保留在正文，不要求平台支持图片、Markdown 或按钮。

## 暂停、修改和不确定结果

先暂停再修改源地址，恢复后重新建立基线。暂停和取消只能阻止后续轮询，不能撤回已经开始的投递。每条订阅持有自己的持久去重游标，不读取聊天订阅的已读表。

投递前先持久记录未确认状态。只有获得确认消息 ID 才恢复待轮询；平台明确未投递时停止该订阅。`unknown`、缺少确认 ID 或进程中断均不自动重试，也不提供恢复按钮。先查看原会话并对账，取消后另建订阅会重新建立基线，不补发旧文章。

管理员订阅与聊天订阅分别管理。`rss-list`、`rss-remove`、`rss-check` 不会读取、取消或触发管理员任务。聊天命令目前拒绝带父容器或话题的地址；管理员入口可保留这些字段。

## 静默时段内先汇总

静默默认关闭，仅适用于显式启用的管理员 RSS 订阅，不改变定时提醒或聊天订阅。在任务参数中同时填写：

| 参数 | 示例 | 含义 |
| --- | --- | --- |
| `quietTimezone` | `Asia/Shanghai` | 明确的 IANA 时区，不猜服务器或使用者时区 |
| `quietStart` | `22:00` | 开始分钟，包含此分钟 |
| `quietEnd` | `08:00` | 结束分钟，不包含此分钟 |

时间使用 24 小时制，可以跨午夜；开始与结束不能相同。三项必须同时填写，全部省略或全部留空关闭；只填一部分会拒绝保存。编辑前仍需暂停订阅。

静默中照常按实例轮询源站，检测到的新文章和待发摘要在同一次持久更新中保存。退出静默后的首轮轮询先发送已积累摘要，该订阅下一轮再抓取源站；已有摘要不会因为源站当时失败而卡住。这里没有承诺在结束分钟精确发送。夏令时按每次轮询时实际的当地分钟判断，不推算有歧义的未来时刻。

摘要按每条订阅和完整目标分别积累，不跨源、账号或会话合并。最多保留 3 条短标题与可用 HTTP(S) 链接，实际展示还受 `maxItems` 限制，其余提示查看源站；检测计数到 10000 后使用“至少”说明。源返回的 20 条窗口与 64 条去重游标限制仍然存在，摘要也不提供永久归档或无遗漏保证。

**暂停会清空待发摘要**，编辑和取消也不保留旧摘要。恢复后的首次成功抓取只建立新基线，不补发。已经领取并开始投递的消息不能撤回；摘要投递结果未知时停止自动处理，只允许核实后取消。

游标和摘要共享实例 60 KiB 状态上限，创建或修改时为有界摘要预留空间；不足时拒绝变更并保留现有数据。内部记录在原 owner 和键中升级为版本 2，新版本可读旧记录；旧 worker 不认识版本 2 时会停止处理，不能回滚旧包后绕过静默策略。

## 轮询窗口与容量

每轮检查源返回的前 20 条，不追溯更早页面。`maxItems` 默认展示 5 条；同轮发现更多新文章时附上省略数量和源站提示，所有已检查文章进入游标，省略项不会下轮补发。首次及恢复基线也只覆盖当轮窗口，因此不提供永久归档或无遗漏保证。

每实例最多 8 条管理员任务，保留最近 32 条操作回执；每条订阅保留最近 64 个条目标识摘要。取消或失败历史可在新建时整理，未确认任务不能自动丢弃。格式损坏时保留持久数据并停止管理员轮询，不自动清空重建。

更多操作与响应丢失后的核对方法见[管理员任务中心](../paths/console.md#管理员任务中心)。
