# 不启用 AI，也能设置提醒

安装持久提醒插件后，在聊天里发送 `remind create 十分钟后 喝水`。Bot 显示明确的执行日期、时区、内容和投递会话，回复 `确认` 后才保存。缺少时间或内容时会逐项询问，不需要模型或 Agent。

## 先确认实例和时区

按[提醒插件 README](https://github.com/zhinjs/zhin/tree/main/plugins/utils/reminder) 安装并加载插件，同时启用持久 Database Host 与所需的 Schedule Feature。缺少持久数据库时插件启动失败，不会只存在内存里。

在对应提醒插件实例中设置 `timezone`，例如：

```yaml
timezone: Asia/Shanghai
```

默认是 **UTC**。新 `create` 指令中的本地日期使用这个配置，不猜服务器或发送者时区。原有 `at`、Console 和 Agent 的绝对时间仍要求显式 offset。

## 创建并确认

以下例子假设账号前缀为 `/`，且未配置插件命名空间。实际使用时按当前账号和实例调整：

```text
/remind create 十分钟后 喝水
/remind create 明天九点 开会前检查资料
/remind create "明天下午三点半" 提交周报
/remind create 2027-01-01T09:00:00+08:00 新年会议
```

只输入 `/remind create` 也可以，Bot 会分别询问时间与内容。时间表达含空格时，在指令参数中加引号；补问时可直接输入完整表达。

核对显示的绝对日期、时区、内容与原会话，再回复 `确认`。确认前没有任务，等待也不会让显示的时间自动顺延。后续回答不加命令前缀；输入 `取消` 或 `cancel` 可退出。需要换一个流程时，先取消，再重新发送指令；补问期间再次发送命令可能被当作当前回答。

创建后用 `/remind list` 查看，用 `/remind cancel <任务 ID>` 取消自己的提醒。创建成功表示任务已持久保存，到点是否收到消息还取决于平台和实际投递结果。

## 支持的时间

| 表达 | 含义 |
| --- | --- |
| `十分钟后`、`2小时后`、`一天后` | 固定间隔；一天按 24 小时计算 |
| `今天18:30`、`明天九点`、`后天九点半` | 配置时区中的日期与时钟；没有时段词的九点是 09:00 |
| `明天下午三点半`、`明天晚上九点` | 配置时区中的相应时段 |
| `2027-01-01T09:00:00+08:00` | 使用明确 offset 的 ISO 绝对时间 |

这是有限语法。裸写 `九点` 不会猜今天或明天，已经过去的 `今天九点` 也不会自动改成明天。`每天九点`、`每周一` 等日历周期不在这条路径中；原有 `/remind every 3600 喝水` 表示固定秒数，不能当作跨夏令时的每天同一时间。

夏令时使本地时刻不存在或重复时，改用带 offset 的 ISO 时间，Bot 不会替你选择。输入或确认超时不创建任务，整个流程有总时限；反复输错不会无限延长。插件退役或运行代切换会结束旧补问，需重新发起。

## 投递和归属

聊天创建的是个人提醒，只发回创建时的完整会话：账号、会话种类与 ID、父容器和话题均保留。其他发送者、其他 Bot 账号或同名话题不能读取或取消它。

补问与确认均可用普通文字，不要求平台支持按钮、Markdown 或图片。不同平台仍走统一消息链；投递不确定时不自动重试，先核对原会话和任务状态。

Console 的[管理员任务中心](../paths/console.md#管理员任务中心) 管理另一类任务，由管理员明确选择目标。它的时间字段目前使用含显式 offset 的 ISO 时间，本页能力不会自动扩展到管理员任务。
