# 只在选定的群欢迎新成员

群运营套件的 `welcomeConversations` 可以把欢迎限制到一个 Bot 的一个完整群会话。这个设置只影响成员加入时的欢迎，不改变签到、词库、统计或命令权限。

## 先选择实例，再选择群

在 Console「任务中心 → 按用途开始」选择“配置新成员欢迎”，进入 `/use-cases/group-welcome`。使用具有管理权限的连接；Demo 不读取或修改此流程。新版 Console 与 Host 分开更新，旧界面没有该入口时仍可使用原插件配置与详情页。

流程从 Host 用途目录读取[群运营套件](https://github.com/zhinjs/zhin/tree/main/plugins/utils/group-suite)的包身份，列出该包的可管理实例。相同包可以有多个实例，必须明确选择，不默认选第一个。尚未安装时进入市场查看该用途的包，审阅具体版本和原有安装计划；打开市场本身不会安装。结果不确定时先核对安装状态，不重复提交；成功后继续选择 Host 实际返回的实例名。

1. 填写 `welcomeMessage`，例如 `欢迎 {name} ({id})`。空文案仍表示关闭欢迎。
2. 在 `welcomeConversations` 点击“限定到所选会话”。此时先设为空范围，不会立即扩大生效范围。
3. 添加精确会话，读取当前 Host 账号并选择实际 Bot，再填写群 ID；平台有父容器或话题时，保留对应 ID。
4. 核对摘要，通过原表单的 Host 校验并保存，再按引导到插件详情申请应用。编辑草稿不等于已经生效。
5. 返回群欢迎流程，重新读取当前实例与运行代证据；配置语义已匹配后，再核对文案、范围和完整测试群。此时仍未证明平台欢迎成功。

没有群目录查询的平台需要手填真实群 ID，但账号仍从 Host 返回的完整 Endpoint 选择。不要用显示名、本地账号名或自行拼接的 ID 代替。

手工编辑配置时，可先以空范围准备文案，再通过 Console 选择目标：

```yaml
configVersion: 2
plugins:
  group-suite: '@zhin.js/plugin-group-suite'
group-suite:
  welcomeMessage: '欢迎 {name} ({id})'
  welcomeConversations: []
```

## 三种范围含义

| 配置 | 生效范围 |
| --- | --- |
| 省略 `welcomeConversations` | 实例收到的所有符合欢迎条件的群事件 |
| `welcomeConversations: []` | 不欢迎任何会话 |
| 列出完整会话 | 只匹配这些精确会话，最多 100 项 |

账号、会话类型、ID、父容器和话题共同参与匹配。两个 Bot 在同一个群里不会因为群号相同而共用白名单。省略父容器或话题，只匹配同样没有该身份的事件，不表示包含全部子频道或回复串。重复列出同一会话也只欢迎一次。

移除最后一个条目会留下空列表，保持关闭；“恢复覆盖全部”会删除范围限制，Console 会再次确认这次扩大。欢迎始终发回实际事件的原会话，白名单不能把消息转发到另一处。

## 怎样记录一次真实欢迎核对

在用途页选择完整测试群，与群成员约定后，由成员真实加入，再到原群和日志核对该实例的欢迎。Console 不伪造入群事件、不代替用户发送测试消息，也不把普通测试发送当作成员加入链路。多个实例可能处理同一事件，请自行核对欢迎来自所选实例；系统不会自动完成这项归因。

确认观察后，勾选说明并点击“只读核对后记录人工确认”。页面会重新读取现有文件、插件应用与运行代证据，绑定本次实例和完整目标。空文案、空范围、未应用或不匹配的测试目标不能记录为可用。保存与应用仍由原配置表单和插件详情负责，用途页不新增一套写配置或执行验证的接口。

这条记录始终标为**人工确认**，不是 Host 或平台自动验收，也不保证持续可用。它仅保存在当前页面内存；离开或刷新会丢失。连接、实例、配置、运行代或完整测试目标改变，以及证据重读失败时，原确认失效。页面每 10 秒只读核对一次，存在观察间隔。

::: warning 环境引用不是非空文案的证明
插件仍支持环境变量引用；但用途页只读取原始保存配置，不读取或展示展开值。`welcomeMessage: '${WELCOME_TEXT}'` 在实际运行时可能展开为空，范围中的引用也可能改变真实身份。首版遇到这些引用会保守标记为无法证明文案或范围，不允许据此记录可用；请通过原配置、环境管理和真实群结果自行核对。这是用途页的证据限制，不是禁止插件使用环境变量。
:::

## 与 Agent 会话欢迎的关系（ADR 0037）

群欢迎的用户入口仍是群运营套件：`welcomeMessage` / `welcomeConversations` 在这里配置、验收和排查（[#1012](https://github.com/zhinjs/zhin/issues/1012) A9）。ADR 0037 第 1 期切片 A（[#1019](https://github.com/zhinjs/zhin/pull/1019)，评审中，不能当作已合入）另在 Agent 侧按会话提供模板欢迎 `welcome.enabled`，过控制面与 session-gate；它不读取本插件配置，本插件也不读取它。

两者在同一会话同时开启会各发一条欢迎。统一为单一路径之前，每个群只开一种：

- 用群运营套件欢迎：保持 Agent 会话的 `welcome.enabled` 关闭（默认即关闭）。
- 改用 Agent 会话欢迎：把该群从 `welcomeConversations` 中去掉，或清空 `welcomeMessage`。

退群时群运营套件不发送任何消息；退群记录由 Agent 侧审计负责。

## 没有欢迎时看哪里

适配器必须上报带明确群目标的 `notice.group.member_increase`。没有这类事件，或事件没有可回复目标时，不会猜测一个频道发送。配置匹配只证明范围符合，不证明平台在线或消息已送达。

检查实例是否应用、文案是否为空、白名单完整身份是否与事件相同，再看实际投递结果。投递未知时先核对原群，不自动重试。真实平台测试可能向群发送欢迎，请在准备好测试群后明确执行。

命令的 `group(id)` 只比较会话类型和 ID，不能代替这里的完整会话白名单。需要理解命令规则时，见[Console 权限说明](../paths/console.md#命令权限说明)。
