# 运营与群管指南

这一页写给**运营、群主、社群 / 客服负责人**：你负责让 Bot 在群里好好工作，但不写 TypeScript。你需要的一切都在浏览器里的 **Console** 和一份配置文件里。

::: tip 这页适合你吗？
- **适合**：想给群配欢迎语、签到、提醒、订阅推送、内容审核，想看 Bot 在干什么、出了问题能先自己查。
- **不适合**：想写新命令、新插件或接新平台——那是开发者的事，请看 [开发者快速开始](/getting-started/)。
:::

## Zhin 能帮你做什么 {#what-you-get}

| 你想要的效果 | 怎么得到 | 需要写代码吗 |
| --- | --- | --- |
| 同一个 Bot 同时管 QQ、微信、企业微信、飞书、Discord 等多个平台的群 | 开发者部署一次，你在 Console「聊天账号」里统一查看 | 否 |
| 新人进群自动欢迎，只在指定群欢迎 | [群欢迎指南](/solutions/group-welcome) | 否 |
| 签到积分、消息统计、群问答 / 关键词回复 | 在「功能商店」安装群运营套件 `@zhin.js/plugin-group-suite` | 否 |
| 定时提醒、活动提醒 | [不启用 AI 创建提醒](/solutions/reminders) | 否 |
| 把订阅更新推到指定群 | [管理员 RSS 订阅](/solutions/rss-subscriptions) | 否 |
| 拦截广告、辱骂等不当内容 | 安装内容审核插件 `@zhin.js/plugin-content-moderation` | 否 |
| 一个会聊天、能回答业务问题的 AI 助手 | 开发者开启 AI 后，你在 Console 里观察和止损 | 开启时需要开发者 |
| 公告「人批了再发」、危险群管动作先审批 | 见下文 [群管、公告与审批](#group-ops) | 否 |

还没决定要不要用？先打开 [在线 Demo](https://demo.zhin.dev) 看看 Console 长什么样（Demo 是只读的）。

## 连上 Console {#connect-console}

Console 是独立的网页后台，不需要你部署：

1. 向部署 Bot 的人要两样东西：**API 地址**（例如 `http://127.0.0.1:8068` 或你们的域名）和 **Token**（项目 `.env` 里的 `HTTP_TOKEN`）。
2. 打开 [console.zhin.dev](https://console.zhin.dev)，填入地址和 Token。
3. 看到首页里的账号（Endpoint）显示在线，就连上了。

::: warning Token 就是密码
不要把 Token 发到群里、放进截图或链接。Token 分两种：**Full token** 可以发消息、改配置；**Demo token** 只能看。日常只看状态的同事给 Demo token 就够了。
:::

还没有一个在运行的 Bot？这一步需要开发者或运维做一次：按 [快速开始](/getting-started/) 创建项目，或按 [部署与恢复](/operations/production) 上线。之后的日常运营都可以在 Console 里完成。

## 日常运营：按任务找页面 {#daily}

| 我想… | 去 Console 的页面 |
| --- | --- |
| 看 Bot 是否健康、哪个账号掉线 | 首页 |
| 给某个群 / 私聊发消息，看最近消息 | 聊天账号 |
| 回看 Bot 和大家聊了什么 | 聊天记录 |
| 不用真实平台先试一下回复 | 试聊一下（Sandbox） |
| 看 AI 为什么回 / 不回、调用了什么工具 | 机器人状态（含决策回放） |
| 让 Bot 立刻安静 | 机器人状态 → 控制面（见 [一键止损](#stop)） |
| 管理定时提醒 | 定时提醒 |
| 安装 / 停用功能 | 功能商店、功能管理 |
| 按用途一步步配置（如新成员欢迎） | 任务中心 → 按用途开始 |
| 查错误 | 运行记录 |

每个页面的详细说明见 [Console 管理路径](/paths/console) 和 [Console 参考](/console/)。

## 不写代码改配置 {#no-code-config}

Bot 的行为由一份配置文件 `zhin.config.yml` 决定。你不需要直接编辑文件：

- **装功能**：在「功能商店」搜索并安装插件，在「功能管理」里启用或停用。
- **改功能设置**：在插件的配置表单里改，比如欢迎语、签到积分、词库上限。表单按插件声明的字段显示，填错格式时不会让你保存。
- **改密钥**：平台凭据、模型 Key 等放在「高级 → 环境变量」，不要写进普通配置。
- **确认已生效**：保存成功不等于已经生效。按页面提示区分「需要重启」和「插件配置待核对」，必要时点「读取应用证据」核对；功能是否真的在跑，以「运行时能力」页面为准。

::: details 习惯用终端？
在 Bot 项目目录里运行 `npx zhin setup` 可以按向导添加平台、AI、数据库；`npx zhin doctor` 一键诊断端口、Token 和配置。完整字段见 [配置参考](/configuration/)。
:::

## 群管、公告与审批 {#group-ops}

Zhin 的原则是：**Bot 的每个决定可以追溯，危险动作不批不做，出事能一键止损。**

### 入群欢迎与群运营

- **欢迎新成员**：群运营套件的欢迎语默认关闭，设置欢迎文本后才发送；可以只在指定群欢迎。步骤见 [只在选定的群欢迎新成员](/solutions/group-welcome)。
- **签到、统计、问答**：安装群运营套件后，群友用 `签到`、`stats` 等指令；**只有群主、管理员或受信任的人**能修改关键词和问答。
- **内容审核**：内容审核插件对进出消息扫描，按严重程度拦截或打码。

### 公告：起草 → 审批 → 发送

- AI 可以帮你**起草**公告，但不能自己提交、批准或发送。
- 有审批权限（Console 权限 `ops:approve`）的人批准后才会发出；批准后改过正文的公告会被拒发。
- 待审批超过 24 小时自动过期；发送失败不会偷偷重试，在 Console 里能看到原因，需要再批一次才会重发。

### 危险动作审批

踢人、跨群发消息、改配置这类危险动作，Bot 只会生成一张**审批卡**，由有权限的人批准或拒绝。同一个群的同一类动作有冷却时间，连点也只会生成一张卡。群聊里还可以选择「仅本次 / 当前会话 / 始终允许」等审批范围，详见 [AI 审批方式](/ai/#ai-agent)。

### 一键止损 {#stop}

在「机器人状态」的控制面里，有四个开关，可以对整个 Bot 或单个群生效，重启后保留：

| 开关 | 效果 |
| --- | --- |
| 紧急停止（`emergency_stop`） | 不进模型、不发任何消息（包括定时通知） |
| 静音（`muted`） | 不发言 |
| 只读（`read_only`） | 不做任何写操作 |
| 仅 @ 时回复（`mention_only`） | 只有 @ Bot 或私聊才回复 |

AI 没有任何办法自己关掉这些开关。每次拦截和改动都会记在决策回放里，事后能查到是谁、什么时候改的。

::: info 现状说明
公告、会话欢迎、会话日程和控制面的能力已经在 Bot（Host）里提供；部分对应的 Console 页面仍在陆续上线，旧版 Console 可能看不到入口。看不到时请升级 Console，或请开发者协助。按规则**自动禁言**的「动态群管规则」仍在规划中（[#1050](https://github.com/zhinjs/zhin/issues/1050)），目前群管动作都需要人工审批。
:::

## 出问题时先自己查 {#troubleshooting}

1. **首页**：Bot 连上了吗？账号在线吗？
2. **聊天账号**：群友的消息到达 Bot 了吗？可以打开那条消息的「诊断」。
3. **运行时能力**：相关的功能加载了吗？
4. **机器人状态**：AI 执行到哪一步、为什么没回？

更多见 [消息没有回复](/troubleshooting/messages) 和 [故障排查中心](/troubleshooting/)。

## 什么时候该找开发者 {#when-to-call-a-developer}

| 情况 | 原因 |
| --- | --- |
| 第一次部署 Bot、换服务器、升级大版本 | 需要命令行和服务器权限，见 [部署与恢复](/operations/production)、[版本兼容与迁移](/operations/upgrades) |
| 想要一个现有插件做不到的新命令或新功能 | 需要写插件，见 [第一个插件](/getting-started/first-plugin) |
| 想接一个还没有适配器的平台 | 需要写适配器，见 [适配器开发](/authoring/adapters) |
| 想让 AI 能调用你们的业务系统 | 需要写 AI 工具，见 [Agent 工具](/authoring/agent-tools) |
| Console 连不上、跨域报错、反向代理问题 | 需要改服务器配置，见 [部署与恢复](/operations/production) |
| 运行记录里有你看不懂的报错 | 把报错和时间发给开发者，见 [故障排查中心](/troubleshooting/) |

找开发者时，附上：哪个群、什么时间、你期望发生什么、实际发生了什么，以及「机器人状态」或「运行记录」的截图（注意遮住 Token）。
