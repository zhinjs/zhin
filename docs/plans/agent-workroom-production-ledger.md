# Agent Workroom 生产化 Ledger

本文件追踪决策原型已经证明、但尚未吸收到生产模块的工作。决策地图回答“应该怎样”；本 Ledger 防止原型结论被误认为已经上线。只有代码、迁移、测试和文档全部完成后才能勾选。

## P1：Workroom Agent Identity Projection

Status: in_progress

Production slice 1 (2026-08-22): 已新增 crash-durable Projection Outbox、Message Index 与 Journal tracer；Project/Run/Task/Assignment/Agent/binding/policy identity 随 projection 固定，File repository 通过 immutable snapshot、digest 与 create-only CAS 支持多实例和重启。generation-owned bounded scheduler 从 persistent Workroom Catalog 复验已认证 canonical conversation binding，扫描 Journal durable cursors，恢复 pending/expired delivery，并经 `messageGatewayToken` 的统一 IM outbound chain 投递；失败按同一 idempotency key 重试，dispose 会 abort 并 join 当前 tick。`assignment.progress` 不逐条刷群：按 policy-pinned 固定窗口聚合 Kernel 顺序事实，未闭合窗口不推进 durable cursor，重启可重放且不重复；milestone/attention/conclusion 立即闭合并投影。Reviewer/Sponsor/lease/rework/cancel 控制事实已投影为有界 attention，不序列化任意 payload。Human ingress reply 通过 durable Message Index 与当前 Kernel Assignment read projection生成 TaskInput target，discussion 与历史 Assignment 不获得 Task writer。P12 materialized Disclosure Manifest 尚未接入 Projection Outbox，因此 P1 保持 `in_progress`。

## P2：Deterministic Workroom Scheduler

Status: in_progress
Source: decision map #2 and `packages/im/agent/prototypes/workflow-scheduler/`

- [x] Scheduler 以 `Journal facts + pinned Scheduler Policy Snapshot` 为纯输入，同一 sequence 产生同一 content-addressed decision；排序固定覆盖 reservation、starvation、Sponsor lane、deadline、lane rank/aging、enqueue sequence 与 Task key。
- [x] Plan Admission 将受信 planning adapter 固定的 Scheduler Policy 与逐 Task scheduler facts 原子写入 Run Journal；Scheduler 不读取模型 metadata 或运行时 config 猜测 lane。
- [x] dependency 只由上游 `task.accepted` 满足，accepted 后下一 ready Task 自动成为确定性 head；execution-completed 不放行下游。
- [x] Kernel 重新计算 exact decision 后才以 `expectedSequence` CAS 写 durable `scheduler.dispatch_requested`；多实例 loser 重放，重启恢复 pending dispatch。
- [x] Sponsor 跨 lane 与 Orchestrator lane 内 rank 变更具有 typed proposal，跨 lane Orchestrator proposal fail closed；等待元数据缺 owner/deadline/cancel successor 时禁止调度。
- [ ] 完成 generation-owned Local/Remote Assignment supply：标准 Host 已接 Local production producer，经 pinned Profile/Catalog exact role route、Acceptance Contract 与 Kernel Local issuance 启动 Agent execution；Remote supply 仍须在启用 A2A 且存在 Profile Remote Authority 时完成标准 Host route composition。无/多义 route 或无 producer 会进入 owner/deadline/cancel-successor 完整的 durable capability blocker，后续 supply generation 自动 resolve。
- [x] 完成 Plan Revision/动态子任务的 Kernel CAS admission、Sponsor priority proposal authority verifier、checkpointable 两阶段 preemption/reservation consumer 与超时结算；atomic Task 不得伪装可抢占。
- [ ] 增加 Console/Sponsor Room queue/control projection 与完整 E2E（插队、持续 urgent 下 starvation、CAS、重启、cancel/replan、accepted 自动推进到本地/远程 Executor）。

Production slice 1 (2026-08-22): 已落地 production `WorkroomScheduler` pure decision、Kernel CAS command、generation-owned recovery runtime 与真实 `admitWorkflowPlan → pinned policy/task facts → scheduler.dispatch_requested` E2E。pending dispatch 是 durable outbox fact，重启先重投再选择新工作。标准 A2A composition 在 current Profile Remote Authority 存在时会注册 remote supply，经显式 Assignment Route Port 精确选择 Agent/endpoint、pin Acceptance Contract，并调用 Remote Assignment Dispatch Command；authority 缺失不伪造 Assignment。无 supply 时 Scheduler 不写 dispatch fact，而通过 typed Kernel command 写 owner/deadline/resolve-replan-cancel 完整的 capability blocker；route 多义时 pending dispatch 同样转为 visible blocker，后续 supply generation 可自动 resolve。Local producer、Sponsor/Orchestrator priority authority-backed Kernel writer、两阶段 preemption 与动态 Plan Revision仍未闭环，因此 P2 保持 `in_progress`，不得标记 production absorbed。

Production slice 5 (2026-08-22): 组合级 Host/Kernel fixture 已固定剩余跨模块不变量：chat 保留 `spawn_task` 但执行不产生任何 Workroom Journal fact，Workroom Assignment 物理移除 spawn/typed writer，纯 PlanBuilder 前后 Journal 均为空；Local 与 authenticated Remote completion 归一为同构 `assignment.execution_completed` 且只到 `awaiting_acceptance`；只有 `task.accepted` 才推进 dependent Local Assignment。持续 urgent 输入下，超过 pinned starvation bound 的 low lane Task 仍先行且 lane 不被改写。Remote Assignment 缺 typed checkpoint provider时写带 resolve/replan/cancel 的 durable blocker，重启安装 provider后只重投 request、不伪造 ack；generation retire会 abort在途 delivery。既有 Kernel cancel、Plan Revision `preemption_required` 和 timeout blocker tests继续作为同一SSOT gate。剩余缺口收敛为 Console/Sponsor Room projection、Remote supply composition与外部typed checkpoint transport实装，P2保持 `in_progress`。
