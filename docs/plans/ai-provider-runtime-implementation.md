## Evidence and limits

- Independent validation checkpoint through backend `564476d32`: ROOT's actual CI-selected build completed 114/114 tasks; final contracts passed (`/tmp/zhin-provider-final-ci-contracts.log`). Full `check:all` remains in progress (`/tmp/zhin-provider-final-check-all.log`), so its completion and final eval outcomes remain unverified at this edit.
- **Historical checkpoint before Database type isolation:** the actual 26-package Agent tarball closure was reinstalled with the corrected authoring declaration. Its strict compiler result retained four baseline optional-dialect dependency errors (`mongodb`, `mysql2/promise`, `pg`, `redis`); the nonexistent root `AIHookEvent` reference was gone. Four formal Agent runtime entry imports passed with zero provider calls. This checkpoint did not establish a green full Agent strict closure; no optional databases, shim or skipLibCheck hid those errors (`/tmp/zhin-provider-final-agent-archive-strict.log`). The subsequently approved Database isolation is implemented: neutral root plus Memory/SQLite, explicit external-dialect entries, and the separate PostgreSQL declaration contract. The 29-package real-tarball matrix passed its six consumers; see the [current Database contract and evidence](./database-optional-dialect-types.md).
- Owned-source Host checkpoint after security review: 27 files / 190 tests passed, including Session-only real CLI, Host HMR / approval, native Fetch + GC, ambient metadata and SQLite dialect contracts. Focused ESLint passed. The Agent dependency build completed 32 tasks, then CLI typecheck passed against its rebuilt child-perception declarations. These are local checkpoints, not the final immutable-candidate repository gates.
- Repository/auth/management checks use synthetic data with real local SQLite and the Host cipher. HTTP tests use temporary loopback listeners. Native transport acceptance uses an actual local HTTP server and forced GC; it is not a vendor call.
- Real CLI upgrade test executes `zhin migrate inference` preview → apply → finalize, then `runStartCommand`; authenticated management works, anonymous access is 401 and external request count is zero. ROOT independently reproduced this. It uses development source entry points, not a released tarball.
- Original startup failure was reproduced before correcting cleanup registration: `handoff.activateNext` cannot add to an already sealed DisposeStack. Cleanup is now registered in preparation; activation only captures its exact Driver ownership.
- SQLite JSON red/green checks use actual `StatementSync.columns()` table/original-column metadata. Same-name JSON/TEXT columns, aliases, joins, expressions without provenance and attached databases preserve their own contracts; the existing Session text store has no compensating decoder.
- Management view projects one captured graph for all account statuses. The 100-account actual SQLite test observes one graph read and 100 credential reads; ordinary status, inference and writes retain live identity checks.
- OAuth window dismissal hides a resumable, single account-owned challenge. Only explicit cancel, disconnect, removal or Host close ends it. No TTL was invented; an uncompleted challenge does not survive process restart.
- Credential transport facts are private and in-flight. Request-to-version association lasts while its final Request remains held. It is not persistent auditing and does not provide historical querying when no private observer is installed. Observer sync/async failures cannot change transport results or authentication state.
- `ai.plan.yml` exports metadata and explicit bindings, never Key/token/client-secret or sealed private records. Cross-Host import must deliberately bind actual destination identities or create new ones.
- Source preview never loads `.env`, another CLI's authorization cache or executable project plugins. It reports unresolved mapping/owner/session references instead of replacing them with defaults. Official automatic import and explicit existing-Profile Session binding remain different reviewed units sharing the same journal/CAS mechanism.
- Normal API saves do not write the startup file. Offline migration finalization is a separate explicit operation, preserves the original source in a private backup, and does not restart the process. Database and file cutover are not claimed to be one transaction.
- Existing process-owned AssistantStatus ambient scenario configuration is still bound by ingress construction; candidate-config residue is a pre-existing boundary outside this change. New model metadata uses the actual Console operation scope and canonical ambient selection rather than the removed static judge selector.
