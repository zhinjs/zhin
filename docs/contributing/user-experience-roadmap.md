# 用户体验优化路线

本路线跟踪 [Issue #829](https://github.com/zhinjs/zhin/issues/829)。目标是让使用者更容易配置一个实用功能，理解它在哪里生效，并在执行失败后自行定位原因。框架仍面向生活与工作场景中的多通道 IM 助手，不扩展为独立产研工作流产品。

本文是实施与验收计划。已有基础、正在实现和后续计划分别标注；列入路线不代表功能已经交付。既有安装改进详见[插件体验计划](./plugin-experience-plan.md)。

## 实施状态与顺序

| 批次 | 优先级 | 范围 | 状态 | 依赖 |
| --- | --- | --- | --- | --- |
| A | P0 | 单条入站消息的有界诊断、可读文本降级；Console 展示与排错入口 | 已实现并完成本地回归与夹具浏览器验收；待 PR CI 与真实平台验收 | 当前消息链与当前 generation 快照 |
| B | P0 | 按用途配置的首条任务路径 | 管理员提醒路径已实现，欢迎与关键词提供现有配置指南；待 PR 验收 | 复用安装、配置、应用与业务验证；复用 A 的故障解释 |
| C | P0 | 精确生效范围选择、查看与权限解释 | 任务精确投递目标已实现；入站范围与权限解释待实现 | 完整会话身份；明确各能力的入站或投递边界 |
| D | P1 | 任务中心、自然时间与补问 | 管理员提醒任务中心已实现；订阅、自然时间与补问待实现 | 明确任务 ownership、持久化与 C 的目标选择 |
| E | P1 | 通用准入、配置解释、通知节制 | 待实现 | A 的结果分类；C 的隔离身份；D 的任务状态 |
| F | P1 | 场景试验台、文档与运行时入口连通 | 待实现 | 前述稳定契约与可复现验收场景 |

每批做成可独立评审的纵切片，先交付一条真实用户路径，再扩展用途与适配器覆盖。所有批次使用 Issue 分支与 PR；文档或本地测试通过不能代替前端、完整 CI 或平台实机验收。

## 跨平台的共同边界

### 精确身份

会话和范围必须保留 `ConversationRef` 的全部身份字段：

```text
endpoint.adapter + endpoint.id
kind + id
parent.kind + parent.id（如有）
threadId（如有）
```

`endpoint.id` 是完整的 Endpoint capability id，不能用显示名或局部账号名代替。展示名只用于帮助识别。结构化编码必须区分字段缺省与具体值，不用裸会话 ID 或冒号拼接字符串作为唯一隔离键。

选择一个会话，默认只匹配这个精确会话。是否包含子话题、整个父容器或同类全部会话，必须是显式选项，不能通过忽略 `parent` 或 `threadId` 获得。多账号相同会话 ID、不同父容器相同频道 ID、同会话不同话题均须有隔离回归。

已有 `group(id)`、`channel(id)` 等权限 DSL 的语义不能未经评审就改成上述精确范围。当前权限投影没有完整携带父容器和话题，后续应明确补充契约与准入位置，不把现有快捷字段直接当作精确目标。

### 按目标解析能力

下表是设计与验收矩阵，不是任何平台的固定支持清单。每次操作应根据选定 Endpoint、目标会话、当前 generation 及可用渲染资源解析能力；未声明、未实现或未确认的能力不能显示为已支持。

| 目标具备的能力 | 期望表现 | 不满足时的路径 | 必验边界 |
| --- | --- | --- | --- |
| 仅文本 | 有层次的标题、摘要、编号、可执行的文本指令和可读链接 | 保留核心信息，不暴露 HTML 或内部 Segment 对象 | 长文、特殊字符、无预览链接仍可理解 |
| 原生 Markdown | 使用目标实际支持的语法组织信息 | 不支持的结构转可读文本 | 不把通用 Markdown 支持等同于所有扩展语法支持 |
| 可发送图片，且 HTML renderer 可用 | 对适合的内容生成图片，并保留必要操作说明 | 渲染失败或 renderer 不可用时走可读文本 | renderer 可用不等于目标可收图片；目标可收图片不等于 renderer 存在 |
| 原生按钮或其他交互 | 在已支持的动作协议与生命周期内提供操作入口 | 提供等价文本命令或明确操作路径 | 当前会话、generation、权限、分页边界和禁用状态 |
| 只有图片、没有原生交互 | 图片展示信息，操作放在可读文本中 | 不绘制会让用户误以为可点击的有效控件 | 图片外的指令足以继续操作 |
| 平台缺少目录、角色或状态查询 | 明确显示未知或需确认，允许按规范输入精确目标 | 不伪造列表、权限和在线结论 | 无查询能力与查询失败分别解释 |

所有发送复用[统一消息链](../concepts/message-flow.md)。目标能力的判定、内容降级与平台投递不能形成独立的第二条发送路径。纯预览不发送消息、不执行按钮动作，也不证明真实投递成功。结果为 `unknown` 时不得自动重发；先核实原会话与平台结果，再由使用者选择后续操作。

## 1. P0：从一条消息解释没有回复的原因

**已有基础：** 入站与出站链、Command 准入、Endpoint 状态、日志、Console 会话视图与插件诊断已经存在。当前[Console 排错路径](../paths/console.md)仍需要使用者在多个入口间关联线索。

**本批实现：** 在单条入站消息执行期间记录有界诊断结果，连接 Console 的单消息与当前会话入口；同步改善降级为文本时的可读链接、列表和表格。文本按钮的禁用项不分配操作编号。具体阶段以实现实际记录的范围为准，不将未覆盖的 AI 子步骤、平台回执或自定义中间件行为显示为已观测。

本地已验证 Core 与 Host 回归、独立 Console 测试/类型/构建，并用真实 Runtime 生成的脱敏诊断夹具进行桌面与窄屏浏览器验收。该浏览器验收的 API 使用本地夹具，证明前端展示和交互，不证明真实平台消息投递或已部署版本。

诊断只记录必要的身份、阶段、结果码与经过控制的摘要，不记录消息正文、提示词、完整工具参数、密钥或任意异常对象。记录须有数量与大小上限；首版不默认持久化成完整消息审计库。普通聊天不因为未匹配指令而收到额外错误消息。Console 鉴权与诊断可见性应保持一致。

**端到端验收：** 发送一条正常消息、一条权限拒绝消息、一条执行失败消息以及一条触发渲染降级的消息；授权使用者能找到各自诊断，看到实际观测到的阶段和可操作的下一步。无权限请求不能读取记录，正文与秘密不进入诊断，超出上限后记录有界清理。未命中命令仍按普通聊天链处理。

## 2. P0：按用途配置功能

**已有基础：** CLI 与 Console 已共享安装权威，具备安装计划、精确包版本、配置校验、应用、当前 generation 状态与显式业务验证。它们是复用对象，不再重建安装事务。脚手架与 `zhin setup` 已共享 scaffold-wizard。

**本次纵切片：** `zhin use-cases` 与 Console 读取同一份用途目录。提醒进入管理员任务创建与管理；欢迎和关键词显示现有安装、配置与聊天入口，并明确欢迎当前作用于实例所接收的所有群。管理员提醒实际保存于插件独立持久池，不伪造聊天用户；多实例与精确投递目标必须明确选择。该实现尚未覆盖所有用途的安装到业务验证全过程。

**待实现：** 提供“群欢迎”“关键词回复”“定时提醒”等用途入口，把选择账号、会话、内容和必要依赖串成清晰步骤。用途描述只引用现有插件与配置契约；包、插件实例和业务任务仍由各自现有 authority 管理。计划需显示本次改变、可能发送的消息及未满足条件，完成后区分已安装、已配置、已应用和已验证。

避免依赖仍开放的 [PR #828](https://github.com/zhinjs/zhin/pull/828) 中的插件实例声明变更。首条路径选择现有明确实例；包对应多个实例时要求选择，不能推断别名，也不绑定将被替换的旧声明结构。

**端到端验收：** 在没有该用途配置的项目中，从用途入口完成一项功能，查看精确变更，保存并应用，再在选定会话显式验证。中途断线后先读取真实状态核对，不重复安装或投递；配置冲突时保留草稿。平台缺少目录查询时能理解限制并选择明确目标。验证前不能显示业务成功。

## 3. P0：可视化生效范围与权限解释

**已有基础：** 统一 PermissionHost、builtin permit DSL、真实命令准入与 canonical 会话契约存在；部分插件已经使用完整 DeliveryTarget 隔离持久状态。

**待实现：** 先显示现有范围及其来源，提供精确账号、会话与用户选择，再支持明确的一种能力范围写入。入站触发、出站投递与单条任务目标分别表达。配置归现有 Host 配置 authority，任务目标和业务数据归相应插件；不新增一份与事实脱离的 Console 范围数据库。

权限解释必须说明依据。自定义及平台 permission checker 可以执行任意异步代码，当前没有只读、幂等或无副作用保证，不能为“试算”无条件运行。首版可解释 builtin 规则，将未执行的平台或自定义规则标记为“未评估”；手动填写身份与角色的结果仅是模拟，不得成为正式授权。本文不要求改变现有默认权限语义。

**端到端验收：** 配置账号 A 的一个精确会话，A 的目标消息生效，账号 B 的同名同 ID 会话不生效；parent 或 thread 改变后不自动扩大范围。保存后重新打开能看到一致规则，真实准入与解释无矛盾。未知角色或未评估 checker 不显示为通过，打开试算不会执行自定义 checker。

## 4. P1：统一查看提醒、订阅与定时推送

**已有基础：** 持久提醒、订阅和调度能力已有各自的数据与执行机制，提醒已有失败与投递不确定处理。任务中心不代替这些插件存储。

**已实现首条路径：** `PluginTaskProvider` 在当前运行代发布管理员任务事实，由插件持有 CAS 版本与操作回执。Console 支持提醒创建、暂停、编辑、恢复、取消和未知命令对账；聊天个人任务保持原归属。真实 SQLite、实际 ReminderService 与 HTTP 集成覆盖长正文、幂等重放、过期恢复、未知投递与鉴权。两池共用现有 worker 和批次上限，跨扫描轮转避免管理员任务饥饿。订阅投影及自然时间尚未实现。

**待实现：** 以标准投影展示任务来源、所有者、精确目标、时区、下次执行时间、状态和最近结果；支持来源实际具备的暂停、修改、取消操作。权限由服务端核验，未知能力不生成可执行按钮。

**端到端验收：** 创建任务、重启服务后查看一致状态，修改或取消能反映到真实任务；不同账号与会话任务不混淆，其他使用者不能越权取消。`unknown` 明确提示先核实，不自动重发或伪装失败后重试。

## 5. P1：自然时间与补问

**已有基础：** 提醒有明确时间格式、延迟和周期指令，Agent 提醒工具与对话交互基础存在。不能把新增便捷入口描述成此前完全没有自然语言或交互能力。

**补问前置修复：** 共享问答在提示发送前登记等待，早到回答先暂存，只有发送确认后才交给业务；发送失败、取消、超时、作者退役或运行代切换都会撤销等待。每题按钮使用独立短 callback token，旧按钮和其他能力的回调不能回答当前问题；纯文本仍可输入。Slack 回调保留真实话题身份。该纵切片尚不包含新的自然时间解析或提醒补问命令，不把协议回归当作真实平台发送证明。

**待实现：** 为常见表达提供确定性解析和缺字段补问，先覆盖“十分钟后”“明天九点”等有限范围。创建前后显示解析后的绝对日期、时间、时区及周期语义；“每天九点”与“每隔 24 小时”不能混为一谈。歧义与夏令时边界需明确确认，不靠隐式服务器时区猜测。

**端到端验收：** 不启用 AI 也能完成受支持表达；缺时间时只补问必要字段，超时、取消和多会话并发不串话。跨时区日期、无效时间和歧义表达结果可解释；不支持的表达回退到明确格式。补问按钮不可用的平台能用文本继续同一流程。

## 6. P1：统一冷却、并发与重复触发准入

**已有基础：** 部分插件自有冷却与并发保护，仓库已将公共准入机制列为后续工作。

**待实现：** 在合适的公共链路支持按用户、精确会话或能力限制频率与并发。默认策略及作用位置需单独评审，不能给所有现有指令静默增加冷却。长任务只在有真实状态时显示处理中；取消只有在能终止相应操作时才提供。

**端到端验收：** 同一目标连续触发昂贵操作遵循配置限制，不同 Endpoint 或 thread 不误限流；拒绝时给出可理解原因和可计算的等待时间。抛错、取消、HMR 与 generation 退役释放占用，不出现永久锁死。幂等键和不确定结果不能被普通冷却机制代替。

## 7. P1：配置解释与生效状态

**已有基础：** 配置 Schema、表单、源码编辑回退、revision 检查、应用状态与保留草稿已存在。复杂 Schema 目前采用保守回退，不能为了表单覆盖而丢字段。

**待实现：** 连贯显示已保存、校验中、待应用、当前生效版本及失败原因；查看脱敏后的最终配置及默认值来源。逐步增加复杂 Schema 表单支持，无法完整保留结构时明确回退源码编辑。

**端到端验收：** 保存后展示的是实际文件 revision，应用后展示的是当前 generation；失败不假称生效，冲突不覆盖别人的修改。复杂对象经编辑往返保留未知字段，敏感值不进入默认值解释、诊断或截图。

## 8. P1：通知节制与可管理性

**已有基础：** 现有插件可以产生通知与任务结果，但不等于已有统一静默和摘要策略。

**待实现：** 提供明确时区的静默时段、可选摘要、重复失败合并，以及从通知回到对应任务的暂停或退订入口。紧急通知的例外规则应显式配置。不能通过摘要改变任务事实或掩盖失败。

**端到端验收：** 同一任务的重复失败不会持续刷屏，恢复时能理解恢复了什么；静默期间的通知遵循明确的延后或丢弃策略。静默与摘要按精确目标隔离；不支持交互的平台提供可执行的文本操作。投递 `unknown` 不自动补发整份摘要。

## 9. P1：带场景的插件试验台

**已有基础：** [插件测试工具](../authoring/testing.md)支持实际发现、命令、权限和发送链测试；输出预览已有不发送的边界。

**待实现：** 选择适配器、账号、会话、发送者和输入，展示命中能力、准入原因与目标输出，将场景导出为可运行的回归用例。纯渲染预览与运行插件代码分别进入，不把执行真实插件称为天然安全沙箱；可能产生业务副作用的执行需明确说明并使用隔离设施。

**端到端验收：** 一个场景能导出并在测试运行器复现；同一内容切换能力矩阵，展示真实渲染或明确降级。纯预览不发送、不触发交互、不调用业务工具；执行模式使用独立测试数据，不能接触生产凭据。模拟结果、浏览器结果与实机投递证据分别标注。

## 10. P1：让运行时问题直达文档答案

**已有基础：** [排错目录](../troubleshooting/index.md)、[配置文档](../configuration/index.md)、[命令文档](../authoring/commands.md)与 Console 路径存在。

**待实现：** 为稳定结果码提供对应的文档链接；围绕“每天给群发日报”“只在一个群生效”“安装后为什么不能用”等问题提供短路径。最小示例需有预期结果、适用边界与失败后的检查方式；诊断代码与文档描述保持一致。

**端到端验收：** 从真实错误或拒绝状态进入正确章节，链接无需携带正文、凭据或完整内部异常；示例可在推荐的最小项目执行。文本平台能读到并打开链接，Markdown 和图片路径不会丢失必要操作说明。文档链接检查通过不代替示例执行验证。

## 验证与交付记录

Zhin Host 与独立 Console 是两个仓库。协议、后端权限与测试在 Zhin 仓库验证；页面状态、请求适配、交互与实际浏览器表现须在 Console 仓库分别验证。后端测试通过不说明前端已接入，Console 构建通过也不说明消息已投递。

当前 Host 交付入口为 [PR #831](https://github.com/zhinjs/zhin/pull/831)，直接面向 `main`，包含 [#830](https://github.com/zhinjs/zhin/pull/830) 的消息诊断与文本降级前置，以及管理员提醒任务端口；这些是同一组前置提交，不需要重复实现或重复发版。独立 Console 对应[诊断界面 #14](https://github.com/zhinjs/console/pull/14)与[任务中心 #16](https://github.com/zhinjs/console/pull/16)。[交互可靠性 #832](https://github.com/zhinjs/zhin/pull/832) 仍是独立后续修复。切换 PR 基准或新增提交后，完整 CI 必须按实际 head 重新核验；已有预览检查不能代替未触发的主矩阵。

每个纵切片的 PR 应记录：实际改动、未覆盖能力、回归范围、能力矩阵覆盖、是否做过浏览器或实机验证。验证可分为纯函数与本地测试、Host 集成、Console 浏览器、完整 CI、真实平台五层；没有执行的层次标记未验证。

A 批应先完成单消息诊断及可读降级的后端和前端闭环，再推进 B、C。B/C 的设计与审计材料不能登记为交付；任务中心、自然时间、准入、配置、通知、试验台和文档入口也须按各自验收逐项推进。
