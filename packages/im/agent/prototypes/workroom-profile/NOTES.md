# Verdict

Decision-map ticket #10 is answered by the executable fixtures and scenarios in this directory. The durable conclusions are recorded in the decision map; this prototype is not production code.

- A Profile Revision binds a Project Charter revision, exact Pack id/version/digest set, Project-local Overlay and accepted provenance. Packs never absorb Project learning in place.
- The four Pack kinds have different semantics: domain describes language/schema/roles/workflows, competency provides reusable methods/Skills, integration provides Tool/external supply, and policy tightens governance. Pack inclusion is availability, not Assignment authority.
- A pure compiler catches dependency/digest/definition/schema/glossary conflicts and proves every required Workflow Task has a compatible Agent/capability closure before activation.
- Assignment capability resolution loads only the Task's Skill prerequisite/Tool/Integration/authority closure. Agent ceilings and sibling Profile capabilities remain invisible.
- Profile Curator may propose from accepted sources. Policy may activate only non-expansive knowledge/work-method changes; Charter, Pack supply, schema migration, Tool/external/authority/auto-accept expansion and policy relaxation require Sponsor.
- Runs pin Profile revisions. Rollback creates a new governed revision, keeps history and Run pins, and does not pretend to compensate committed Effects.

Current-code audit: Zhin already has generation-owned Tool/Skill/Agent capability discovery and per-turn capability snapshots, but no Project-scoped Profile Revision, immutable Capability Pack composition, Workflow requirement compiler, Project Memory Schema registry, or governed Profile evolution. Production must reuse the generation capability catalog as available supply while adding Workroom-owned selection/governance; it must not create a second mutable Tool/Skill registry.
