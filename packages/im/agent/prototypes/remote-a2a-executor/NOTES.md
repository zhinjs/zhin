# Verdict

Decision-map ticket #8 is answered.

- `RemoteA2AExecutor` is an Assignment execution adapter, not a remote Task authority. Project/Run/Task/Assignment IDs, revision, attempt, lease, fence and status remain in the local Kernel Journal; A2A task/context IDs are external receipts stored in a Remote Execution Link.
- Admission requires a pinned endpoint/Agent Card digest and a versioned Workroom extension declaring idempotent dispatch, typed Completion Envelope and an allowed workspace provider. A generic text-only A2A agent may discuss, but cannot complete a Workroom Assignment.
- Kernel persists one Dispatch Envelope/outbox item before I/O. It binds Assignment identity, endpoint snapshot, Context View, Acceptance Contract, Capability Snapshot, Disclosure Manifest and Workspace Lease. Retries reuse its exact dispatch/message id; no random identity is regenerated after an unknown response.
- Push/SSE callbacks are an optimization, not correctness. Authenticated deliveries first enter a durable callback inbox keyed by endpoint + event id + payload hash. Exact duplicates are no-ops; one event id with two hashes fails closed; sequence gaps require a polled full-task snapshot. Polling/reconciliation is scheduled from Journal deadlines rather than a process-local interval.
- Callback transport authentication proves who delivered bytes, not that the bytes may mutate a Task. The adapter rechecks dispatch, Assignment/attempt/fence, endpoint, remote task link, callback sequence and typed schema, then proposes ordinary Assignment events through Kernel CAS.
- Discussion/progress never changes Task status. A valid terminal callback produces the same `assignment.execution_completed + Task Report/Candidate` boundary as local execution. It never creates `task.accepted`, merges a PR or updates Project State.
- Shared GitHub work uses a canonical repository ID, immutable base/checkpoint SHA, target ref, per-attempt branch, path scope, integration binding and fence. Credentials remain behind an integration/capability gateway; direct broad GitHub tokens are not a strong lease boundary. Protected canonical branches remain mandatory.
- Completion binds Report/Candidate/Evidence to the leased repository/base/branch and exact head SHA. A PR is only an external Effect/Artifact receipt; its current head, checks or merge state are revalidated by Integration and #7 acceptance. Remote code/artifacts are not copied through A2A text.
- On lease loss or callback conflict, replacement receives a higher fence and a new branch. It may start from an explicitly sealed checkpoint commit, never from a mutable old branch head. Late callbacks and later pushes from the prior attempt are stale; best-effort token revocation/cancel cannot be represented as proof that the remote stopped.
- Cancellation is two-phase and deadline bounded. A missing remote acknowledgement settles local control as `cancelled/lost + outcome_unknown`; potentially started external effects remain in reconciliation. The Run can replan/cancel without waiting for the remote process.
- Exactly-once remote execution is not promised. The contract achieves at-least-once transport, idempotent admission/callback processing, single local terminal append and isolated stale work. If the remote does not support idempotent dispatch, it is not eligible as a mutable Workroom Executor.

Current-code audit: `packages/host/a2a` is an inbound protocol Host backed by `InMemoryTaskStore` and a process-local running map. It starts ordinary Agent Turns with a generic `a2a-client` principal and has no Project/Assignment/Workspace binding. The removed legacy `remote-task-executor.ts` used random request IDs, process-local streaming/poll loops and directly completed/failed orchestration tasks from remote status. Neither path satisfies this contract; production must add an Agent-owned outbound Remote Executor port and durable Journal/outbox/callback projections without reviving `remote_mesh` as a second state machine.

Deferred without changing #8 facts: #9 removes or maps legacy orchestration APIs; #10 supplies domain-specific Remote Agent/Capability Pack registration; #12 governs disclosure of Context, Artifact and Evidence across the A2A trust boundary.
